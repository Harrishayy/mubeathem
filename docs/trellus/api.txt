Authentication and readable scope
Use the API key belonging to your Trellus user. In Trellus, open Settings → Integrations → API (the Call Data API page) to copy your own key. Keep it in a server-side environment variable named TRELLUS_API_KEY.
The key inherits the user’s existing permissions. It is not a separately restricted read-only credential. Verify the readable users with /visible; team_id never grants access.
Do not place API keys in browser code, query strings, analytics, logs, public repositories or prompts. Contact support to replace an exposed key.
This documentation is public. Requests to customer data require authentication and retain your existing Trellus permissions. For an AI assistant that connects through browser sign-in, use the 
MCP setup guide
.

Make your first request
Call /visible first. A 200 response proves the key works and shows the users readable in the requested team.
Call /bootstrap only when you need the full account configuration or exact option strings for filters.
Use metric-details-v7 for totals and breakdowns; use session-list-v6 for rows and transcript snippets.
After choosing one session_id, use /session for complete detail or /get-audio-links for temporary audio URLs.

List and metrics requests use 
Content-Type: application/json

Parameter
Type / requirement
Meaning

integer
Required

end
integer
Optional
Exclusive UTC range end in Unix microseconds. Defaults to now.

string
Optional
One permitted team per request; defaults to the key owner’s team. This does not expand access.

string[]

Two timestamp units:

Convert UTC dates and list timestamps
Copy 
const start = Date.parse("2026-10-01T00:00:00Z") * 1000;

// A returned list started_at value uses seconds:
const startedAt = new Date(started_at * 1000);
Filters and nested fields
cnf
 is an AND list of OR groups: every outer group must match, and at least one condition inside each group must match. An empty outer list adds no extra filter. Avoid empty inner groups.
Each condition needs 
column_name
, 
operator
 and 
value_safe
. Use actual booleans, numbers or strings. 
IN
 and 
NIN
 take arrays. Recognized enum fields accept their names or numeric values; byte values use base64. 
user_log.source
 is a numeric field for list results and filters: use the documented numeric codes, not their explanatory labels.

Read response rows and transcripts
List responses are JSON arrays of positional rows. Each cell follows the request’s select order. [] is a successful query with no matching readable rows.
Top-level request start and end use Unix microseconds. List started_at and started_at filter values use Unix seconds. Durations and transcript offsets are seconds.
Combine turn_data.texts, turn_data.is_customers and turn_data.starts by index. true identifies customer speech; false identifies agent speech.
/session JSON uses camelCase keys and enum names; byte fields are base64. Default-valued fields may be omitted, and wordData is omitted. Without x-proto-as-json: true, the endpoint returns protobuf.
/get-audio-links returns one session object plus aligned audio and audio_links arrays. The URLs expire after one hour. Retention can leave both arrays empty.
Unset proto values can appear as 0, false, empty strings or empty arrays. They do not prove an event was measured. Detection flags are signals, not verified outcomes.
Map list rows, transcript turns and grouped metrics
Copy 
// Example only: select = ["session_id", "started_at", "customer_data.name"]
// Response: [["CALL_ID", 1791849600, "Example contact"]]
const calls = rows.map(row => Object.fromEntries(
  select.map((column, index) => [column, row[index]])
));
const startedAt = calls[0] ? new Date(calls[0].started_at * 1000) : null;
// Transcript columns are aligned arrays:
const turns = texts.map((text, index) => ({
  text,
  speaker: isCustomers[index] ? "customer" : "agent",
  startSeconds: starts[index]
}));
// /session with x-proto-as-json: true uses different JSON spelling:
// { "sessionId": "CALL_ID", "customerData": { "name": "Example contact" },
//   "turnData": { "texts": ["Hello"], "isCustomers": [true], "starts": [0] } }
// Default-valued proto fields may be omitted. wordData is omitted.
// Grouped metrics: selects = [{"cnf": []}, {"column_name": "duration"}]
// Example response: [["Interested", 12, 840]]
// Read as: disposition, count, summed duration in seconds.

Choose aggregations and groups
Copy 
metric-details-v7 uses the reporting column paths from session-list-v6.
Each item in selects produces one numeric result cell:
- { "cnf": [] } counts every session in the time window.
- { "cnf": [[filter]] } counts sessions matching that filter.
- { "column_name": "duration" } sums a numeric or boolean column.
- A select may contain both column_name and cnf to sum only matching sessions.
group_by adds a group value as the first cell in every row:
- { "column_name": "resource_id" } gives one row per rep/resource.
- { "column_name": "user_log.disposition" } gives one row per disposition.
- { "column_name": "dial_metric.is_inbound" } separates inbound and non-inbound calls.
The remaining cells stay in the same order as selects. Use /visible to map resource_id values to user names. Use /bootstrap to discover exact disposition strings.
Each aggregation’s filters are additional to the top-level 
cnf
. A sum can use a numeric or boolean column; summing a boolean counts true values. An empty aggregation object is invalid.
Group numeric values into bins
Use exact grouping for strings, booleans, bytes and enums. Do not supply step parameters for these types.
Floating-point and started_at grouping require step_size_safe and step_start_safe. Integer grouping can use exact values or steps.
step_size_safe is the bin width; step_start_safe is its origin; optional step_modulus_safe is a repeat period. Values use the grouped column’s units: started_at uses seconds.
For stepped groups, the key is floor(((value - origin) modulo period, when supplied) / width). It is a bin index, not a date.
Compatibility exception: the current metric-details-v7 endpoint scales a started_at group key by 1,000,000. Divide by 1,000,000 to recover the bin index before converting it to a time range.
Confirm the key and readable scope
Call /visible first. It returns the readable directory for one team, including user and group IDs. The team field appears only with whole-team read access.
Find real connected-call examples
Use session-list-v6 with conversation_type = 1 and dial_metric.live_duration >= 30. Do not require SIP 200 by default, because processed calls can come from non-Trellus telephony. Include transcript columns when snippets are enough.
Answer aggregate questions
Use metric-details-v7 for counts, numeric sums, and categorical breakdowns. It accepts the same reporting column paths used by session-list-v6. Only fetch session rows when the user asks which calls caused the metric or wants transcript evidence.
Resolve a rep or option name
Use /visible to resolve user names to resource_id values. Use /bootstrap when you also need exact user_log.disposition, user_log.sentiment, or user_log.purpose strings.
Get up to 1000 rows per request
Pass limit in the session-list-v6 JSON body. Use limit: 1000 for bulk pulls, then narrow by rep, disposition, date, call type, or duration. For broader history, split windows that reach the limit and merge rows by session_id; a capped response is not a complete export.
Download audio for one call
Choose a readable call from session-list, then call /get-audio-links with its session_id header. The returned links expire after one hour; request them only when you are ready to play or download the audio.

Errors and troubleshooting
Error bodies can be plain text. Keep the status, endpoint, UTC time and response text when asking support for help. Exclude credentials and customer personal data from logs.
List works, but /session returns 401 “not found”
Send the exact session_id from a list row in the x-session-id header, with the same Bearer key. A session_id query parameter or JSON body is ignored. “not found” means the session could not be located, not that you need a transcript scope. If correct headers still fail, contact support with the session ID, endpoint, status, response text and UTC time; never include your API key.
401 “not permissioned” or “not authorized”
The user behind the key cannot read that session or team. Check /visible and ask your team admin to review reporting access. A team_id parameter does not grant access. “inactive user” can also mean the key is invalid or the account is inactive.
401 “not on db”
The backend found the session record but could not load its stored detail. Report the session ID and response text to support. You can still use transcript columns from the list when available.
400 or rejected phone, company, email or transcript field
Use the exact paths in the field guide. start and select are required for lists; metrics use selects. POST parameters belong in JSON, with Content-Type: application/json. Error responses can be plain text.
200 with [] or missing contact/transcript values
Confirm the UTC date window, readable reps and filters. Remove the live-duration filter to include short calls. Contact data depends on captured CRM enrichment; transcripts depend on recording/transcription settings. A 200 empty result is a successful query with no matching readable rows.
429 Too Many Requests
Wait the Retry-After number of seconds, then retry with a bounded retry policy. Coordinate workers using the same user key. Default backend limits are per user, not per IP. If only your shared cloud host is blocked despite pacing, give support the UTC time, endpoint and response headers so upstream limits can be investigated.
I need every call, not just the newest 50
Set limit to at most 1000. There is no cursor or offset pagination. If a window fills the limit, split it into smaller [start, end) windows and deduplicate by session_id. A full 1000-row response does not prove the export is complete; very dense windows may also need rep filters.
I need a team-wide read-only key, or my key was exposed
A Trellus API key belongs to a user and inherits their permissions; using it for reporting does not make it a separately restricted credential. Each user can copy their own key in Settings → Integrations → API. Use an appropriately permissioned account for team reporting, verify /visible, and contact support for key replacement if it was exposed.

Authentication and endpoint map:
- GET https://ext.trellus.ai/visible — api_key header; optional team_id header.
- GET https://ext.trellus.ai/bootstrap — api_key header; key owner's account configuration.
- POST https://rpt-2.trellus.ai/session-list-v6 — Authorization: Bearer <API_KEY>; JSON body.
- POST https://rpt-2.trellus.ai/metric-details-v7 — Authorization: Bearer <API_KEY>; JSON body.
- GET https://rpt-2.trellus.ai/session — Authorization: Bearer <API_KEY>, x-session-id, x-proto-as-json: true.
- GET https://api.trellus.ai/get-audio-links — api_key and session_id headers.
Call /visible first to verify identity and read permissions. A key belongs to a user;
team_id selects a permitted team and does not expand access. Do not assume a separate read-only key.
Use /bootstrap for exact disposition, sentiment and purpose strings.
List requests require start (Unix microseconds) and select (array of column paths).
end is exclusive and defaults to now. cnf defaults to []; limit defaults to 50, maximum 1000.
For calls, cnf = [[{ "column_name": "conversation_type", "operator": "EQ", "value_safe": 1 }]].
Fields include session_id, started_at, resource_id, customer_address, customer_data.name,
customer_data.title, customer_data.company_name, duration, turn_data.texts,
turn_data.is_customers and turn_data.starts. There is no standard customer email column.
Return rows are arrays in select order; started_at is seconds, not microseconds.
cnf is AND of OR groups. Filter values for started_at use seconds. Turn offsets and duration use seconds.
For counts/sums, use metric-details-v7 with selects: [{ "cnf": [] }, { "column_name": "duration" }].
If grouped, the group value precedes numeric cells. Both column_name and cnf can appear in a select.
Request parameter definitions:
- start: inclusive range start, Unix microseconds; required for list and metrics.
- end: exclusive range end, Unix microseconds; optional, defaults to now.
- team_id: optional report-body team selector; defaults to the key owner's team. One team per request.
- select: required list of exact column paths for session-list-v6; response cell i corresponds to select[i].
- limit: session-list row cap, default 50, maximum 1000; not a page size with a continuation token.
- cnf: optional AND of OR filter groups. [] imposes no extra filter; avoid empty inner groups.
- column_name: exact column path to filter, sum or group; not an alias or display label.
- operator: EQ equals; NEQ not equal; GT greater; GE greater or equal; LT less;
  LE less or equal; IN is one of the value_safe array; NIN is not in that array;
  REGEX searches a string using the backend regex engine (no look-around/backreferences).
- value_safe: typed comparison value, not a stringified JSON value. Booleans use true/false,
  numerics use numbers, IN/NIN use arrays, bytes use base64, recognized enum columns accept names or numeric values. user_log.source is a numeric
  field for list results and filters; use its numeric codes, not the explanatory labels.
- reducer: required only when a filter path contains [*]; ANY = at least one item matches,
  ALL = every item matches. Do not attach reducer to a path without [*].
- selects: required metric-details-v7 aggregation array. { "cnf": [] } counts matching rows;
  { "column_name": "duration" } sums seconds; specifying both gives a filtered sum.
  Boolean sums count true values. Each aggregation's cnf is additional to the top-level cnf.
  Empty {} is invalid. Numeric response cells follow selects order.
- group_by: optional metrics object with column_name; its value is the first cell in each row.
  String/boolean/enum grouping uses exact values; float/time grouping requires step_size_safe
  and step_start_safe. Integer grouping can use exact values or steps.
- step_size_safe: bin width; step_start_safe: bin origin; step_modulus_safe: optional repeat period.
  Steps use the grouped column's units (started_at uses seconds). A step requires an origin;
  do not supply step parameters for strings, booleans or enums. Group cells with steps are bin
  indices: floor(((value - origin) modulo period, if supplied) / width), not timestamps.
  Compatibility note: when grouping started_at, the current endpoint scales that bin index by
  1,000,000. Divide the returned group cell by 1,000,000 before reconstructing a time bin.
Response definitions and defaults:
- /visible users: readable user records, including user_id for resource_id matching.
  user_id_to_email maps known user IDs to email addresses; not every user must have an entry.
  team is included only for whole-team readers; absence does not mean the key failed.
  groups are readable group records; memberships link user_group_id to member_id;
  member_is_group distinguishes a group member from a user member.
- /bootstrap: the key owner's account configuration and option vocabulary, not a call list.
- session-list-v6: JSON array of positional row arrays; [] means no matching readable sessions.
  Each cell's type/meaning is defined in the catalogue below. Results are newest started_at first.
- metric-details-v7: JSON row arrays; with grouping, [groupValue, ...aggregationValues].
  Without grouping, cells follow selects order. Counts and sums are numeric, not session objects.
- /session: SessionData object in protobuf JSON, with camelCase property names, enum names
  and base64 bytes. Default scalar/empty fields may be omitted; missing is not permission evidence.
  Catalogue paths are snake_case list-query paths, not property names to copy into detail JSON.
- /get-audio-links: session is one session metadata object; audio is a recording metadata array;
  audio_links[i] is the temporary URL for audio[i]. Empty audio/audio_links arrays may mean
  recording retention expired. Do not treat session as an array.
- Unset proto values can appear as 0, false, empty string or empty arrays in list cells.
  A default value is not proof an event was measured or a prediction/evaluation ran.
  Sales/quality flags are detection signals, not guaranteed ground truth.
Use the exact session_id from a row as x-session-id for /session, not a URL query or JSON body.
/session JSON is camelCase (sessionId, customerData, turnData) and omits wordData.
Inspect 401 text: not found differs from not permissioned and not on db.
Audio returns { session, audio, audio_links }; links expire after one hour.
Pace list requests at least 2.5 seconds apart. The default application limit is 2 requests
per 4 seconds per user, shared with session-list-v5. Metrics: 4 per 4 seconds; detail: 1 per second.
Honor Retry-After on 429, use bounded backoff for transient 5xx, and read error bodies as text.

windows and deduplicate by session_id; never claim a capped response is a full export.
